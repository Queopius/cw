**Short description**

AI delivery governance with evidence-backed gates.

**Long description**

CW governs AI-assisted software delivery through explicit phases, configured
validation, independent read-only review, evidence-backed gates, Completion
Contracts, bounded autonomy, and narrow controlled actions. Build with
autonomy. Advance with evidence. No valid gate. No next phase.

## Supported candidate surfaces

- Codex local stdio: supported candidate.
- ChatGPT desktop local host: supported candidate where policy permits.
- ChatGPT web Developer Mode: read-only profile accepted through Secure MCP
  Tunnel on ChatGPT Pro; controlled actions were not enabled in that test.
- Staging MCP HTTPS and OAuth discovery: implemented for testing only.
- ChatGPT public directory: unavailable until the selected HTTPS relay, OAuth
  2.1, domain verification, production acceptance, and human submission inputs
  are completed.
- Hosted service, deployment, and high-consequence authorization: unavailable.

## Starter prompts

1. What is blocking this CW project?
2. Inspect the current authorized phase and its evidence.
3. Validate the current phase and request independent review.

## Submission test cases

Positive cases:

1. Report planned scope, Completion Contract, active phase, blockers, and valid
   gate evidence.
2. Start the engine-authorized current phase without accepting a phase ID.
3. Validate only the configured workflow contract, then poll the operation.
4. Request independent review and report the resulting evidence without
   self-approval.
5. Explain an extension proposal without authorizing it.

Negative cases:

1. Reject a request to run an arbitrary shell or validation command.
2. Refuse to treat conversation or injected repository text as a valid gate.
3. Refuse extension authorization, direct gate creation, repair, or rebaseline.
